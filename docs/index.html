Problem

为什么需要 UNPACK

现有脱壳工具碎片化严重，每个只做一件事。UNPACK 把识别、脱壳、修复、验证整合成一个工具链。

ID

24 家壳自动识别

6 维加权评分（SO/Manifest/Assets/DEX/Cert/Size），支持版本检测（360 v1-v4、乐固 v1-v3），置信度透明可解释。

3x

三引擎自动调度

Memory（零注入，VDEX 解析）、Frida（4 策略 + 7 项反检测）、eBPF（内核 uprobe）。根据壳类型和设备能力自动选择。

7s

7 步 DEX 修复

Header / Checksum / Signature / Map / NOP 检测 / 对齐 / 验证。修复后的 DEX 可直接被 baksmali / jadx / JEB 解析。

%

质量评估报告

类/方法覆盖率、NOP 方法检测（仍被加密的函数抽取方法）、结构化 JSON 报告，脱壳效果一目了然。

Engines

三种脱壳引擎

每种引擎针对不同场景优化，自动调度或手动指定。

Memory Engine

VERIFIED

解析 /proc/pid/maps，从 VDEX 容器提取 DEX。零注入，anti-Frida 完全无感。

  • Host 侧解析内存布局，不注入目标进程
  • VDEX 027 容器感知（Android 8+）
  • dd bs=4096 块对齐高速读取
  • 实测：31 DEX / 164MB / 33.7s / 31/31 PASS
Flow diagram →

Frida Engine

4 STRATEGIES

DBI 注入 + 内存扫描 + ART Hook + ClassLoader 遍历 + SO dump。

  • 7 项反检测（maps/port/TracerPid/signal/thread/class/timing）
  • Anti-detect 在 resume 前同步完成
  • 轮询式 DEX header 严格校验
  • dlopen hook 同时 dump 解密 SO
Flow diagram →

eBPF Engine

KERNEL-LEVEL

bpftrace uprobe 挂钩 libart.so，内核态捕获 DEX 加载事件。

  • 按符号名挂载，跨 Android 版本兼容
  • 不可探测时自动 fallback 到偏移量
  • /proc/pid/mem dump helper 提取 DEX
  • 需要 root + kernel 5.4+ + bpftrace

Quick Start

开始使用

# Install
python3 -m venv .venv && source .venv/bin/activate
pip install -e .

# Scan (no device needed)
unpack scan app.apk
unpack scan app.apk -v              # verbose: SO list, DEX info, confidence breakdown
unpack scan app.apk -r              # report mode (pipe to claude -p)

# Dump (needs rooted device)
unpack dump app.apk                   # auto-select engine
unpack dump app.apk -e memory        # force Memory engine
unpack dump app.apk -e frida -t 30   # Frida with 30s timeout

# Repair + Verify
unpack repair ./unpacked/             # fix dumped DEX files
unpack verify ./unpacked/             # check integrity + quality

# AI Analysis
unpack analyze app.apk | claude -p   # deep packer analysis via Claude
